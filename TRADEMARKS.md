## Forks and modifications

See `LICENSE` for what forking and modification rights apply to this project. A fork that **substantially diverges** from the upstream project — for example, by introducing breaking changes or removing core features — must be **renamed** so it is not confused with the official project. Adding a vendor prefix (e.g. "acme-h-cli") is the standard pattern.

If you are unsure whether your intended use is allowed, please open a discussion in the project repository or contact the trademark owner directly.

## Why this policy exists

A license grants clear terms for using, evaluating, and building on h-cli. The trademark policy is the **counterweight** that keeps a single canonical identity for the project — so that when someone says "h-cli", they mean *this* project, not a fragmented constellation of unrelated forks. This is the same pattern used by Linux, Rust, Kubernetes, Python, and most other successful software projects.
